* Executive summary

This report evaluates the static FAVOR-style bitset-filtering implementation
committed as =d29e68c158062dd49fbc06316c1c0bad218e662d= ("Basic FAVOR
kernel working for bitset filters, works best at 1-2% selectivity"). It compares
that implementation with default CAGRA filtering on six dataset/scale
combinations:

- SIFT-1M and GIST-1M;
- BIGANN-1M and BIGANN-10M;
- MSTuring-1M and MSTuring-10M.

The main conclusions are:

1. *SIFT-1M:* FAVOR is clearly better for a 1% filter. Its maximum
   throughput-run recall is 0.95473 versus 0.78369 for default CAGRA. At 10%
   and above both methods reach high recall; FAVOR is competitive but generally
   gives slightly lower large-batch throughput at 50% and 90%.
2. *GIST-1M:* FAVOR improves maximum recall at 1% from 0.76210 to 0.82210,
   although neither method reaches 0.90. From 10% onward the methods have
   similar Pareto frontiers, with small FAVOR latency advantages.
3. *BIGANN:* FAVOR is strong at 1-2%, but its static penalty becomes badly
   miscalibrated above that range. At 10%, maximum recall is only 0.82615 on
   BIGANN-1M and 0.70444 on BIGANN-10M, compared with 0.99827 and 0.99452 for
   default CAGRA. The failure is more severe at 10M scale.
4. *MSTuring:* FAVOR does not collapse, but it also provides no sparse-filter
   recall advantage. At 1%, its recall is approximately equal to or below
   default. At 10-90%, FAVOR is often 4-6% faster at a 0.90-recall operating
   point and has lower low-batch latency, while its maximum recall remains
   slightly lower.
5. *Overall:* the committed method is useful for highly selective filters on
   some datasets, but is not a universally safe replacement for default CAGRA.
   Across all measured datasets, =selectivity <= 2%= is the conservative range
   in which FAVOR can be selected without encountering the BIGANN failure.

* Version and result provenance

The report covers only the committed static FAVOR method and default CAGRA.
It does not include the later passing-result accumulator or experimental static
penalty multipliers.

The cross-dataset measurements were collected using the implementation that
became commit =d29e68c1=. A subsequent matched rebuild compared the current
static path with an isolated build of that exact commit on BIGANN-10M. Across
nine configurations, the maximum recall difference was 0.00009 and the maximum
throughput difference was approximately 0.33%. The 4% recall collapse was
identical in both builds. This rules out the later accumulator refactor as the
source of the reported behavior.

All numbers below are recomputed from the raw Google Benchmark JSON files. No
value is extrapolated. =N/A= means that no measured configuration reached the
specified recall target.

* Scale comparison and interpretation

** BIGANN scale sensitivity

BIGANN-1M and BIGANN-10M use the same vector family and =uint8= distance path,
but independent graphs and delta-d sidecars. The shared qualitative failure at
3-4% shows that database size alone is not its cause. Scale does amplify it:
at 10% the FAVOR maximum falls from 0.82615 on 1M rows to 0.70444 on 10M rows.

Separate penalty diagnostics show that FAVOR with =D=0= can exceed 0.98 recall
on both BIGANN scales, while increasing search width or iteration count does
not fix the normal-penalty result. The graph and final filtering path can
therefore support high recall; the static penalty changes traversal ordering
so that useful passing nodes are not discovered.

** MSTuring scale stability

MSTuring-1M and MSTuring-10M have nearly identical qualitative behavior. FAVOR
does not improve 1% recall, but produces modest QPS and latency improvements at
10-90% when compared at reachable recall targets. Moving to 10M rows does not
cause a discontinuity. This contrasts with BIGANN and shows that the static
formula's behavior depends on dataset and graph geometry, not only scale or
selectivity.

** Why maximum recall and Pareto speed must both be reported

A method can be faster at a reachable target while still having a lower recall
ceiling. MSTuring is the clearest example: FAVOR is usually faster at 0.90
recall but finishes with slightly lower maximum recall. BIGANN at 10% is more
severe: FAVOR appears computationally fast at its low-recall points, but cannot
reach the operating targets at all. QPS comparisons without reachability would
therefore be misleading.

* Conclusion

The committed FAVOR implementation demonstrates that fused penalty scoring can
substantially improve CAGRA search for highly selective filters without a
separate filter-processing kernel. That improvement is real on SIFT and
BIGANN at 1%, and remains useful on BIGANN at 2%.

The static HNSW-derived penalty is not robust across CAGRA datasets. SIFT and
GIST transition smoothly toward default behavior, MSTuring provides only
modest efficiency gains with a small recall deficit, and BIGANN undergoes a
severe non-monotonic recall collapse. The committed implementation should
therefore be treated as an experimental, opt-in search mode. A conservative
cross-dataset selector is:

#+begin_src text
selectivity <= 2%  -> FAVOR may be used
selectivity >= 3%  -> use default CAGRA
#+end_src
