* Scope actually implemented

The original =plan.org= is broader than the implementation and is partly stale.  Current FAVOR is:

- bitset-only;
- supplied one exact selectivity shared by the query batch through =filtering_rate=;
- implemented for explicit =SINGLE_CTA= and =MULTI_CTA=;
- unsupported for persistent search, =MULTI_KERNEL=, and arbitrary UDF FAVOR filtering;
- opt-in through =search_params.filter_mode=, whose default remains =DEFAULT=.

** Delta-d

Delta-d is computed after the degree-32 CAGRA graph exists.  A deterministic bounded BFS collects
candidate neighborhoods, measures the normalized distance gap between ranks =alpha= and =beta=,
and averages valid roots.  The benchmarked configuration is =alpha=10=, =beta=64=, BFS depth 2.

The versioned 80-byte sidecar is bound to graph metadata, logical dataset contents, distance
metric, calculation parameters, and fingerprints.  Loading rejects incompatible or corrupt data.
The follow-up workspace optimizes sidecar generation without changing its API or file format: BFS
duplicate detection uses a shared-memory open-addressed set instead of a quadratic scan, the root
vector is staged once, and candidate distances use CAGRA's 8/16/32-lane team layout for dimensions
up to 128/256/above 256.  GIST-1M delta-d generation now completes in about 36 seconds on the L4;
the former serial-reduction kernel had not completed after 22 minutes.

The CAGRA estimate was compared with the reference FAVOR/HNSW construction and was close enough to
rule out delta-d calculation as the main BIGANN/MSTuring failure.  The full one-million-row
cross-check against the actual =/home/ubuntu/FAVOR/include/favor.h= code used matched
=M=16=/maximum base degree 32, =ef_construction=64, =alpha=10=, and =beta=64=.  CAGRA differed by
2.072% on GIST and 4.268% on MSTuring-1M; exact equality is not expected because the graphs are
constructed by different algorithms.

** Penalty formulas

Let =s= be passing selectivity, =f= be =1-s=, =B= be effective/configured =itopk= as selected by
the search mode, and =delta_d= be the graph statistic.

#+begin_example
D_reference = f * (B - s) * delta_d / (2 * s * B)
#+end_example

Query-local mode derives a robust local distance gap =g_q= from the interquartile span of the
query's finite initial candidates:

#+begin_example
D_query = min(D_reference, lambda * g_q)
#+end_example

Retention-safe mode additionally bounds the penalty for a rejected candidate with raw distance
=d=.  Let =tau= be the worst finite distance currently retained and =h=max(tau-d,0)=:

#+begin_example
D_effective = min(D_query, rho * h)
score = d + D_effective
#+end_example

Because =rho<1=, the penalty alone cannot move a candidate beyond the current retained boundary.
The fixed method uses =lambda=1= and =rho=0.5=.

Setting =favor_retention_fraction= to zero selects the automatic SINGLE_CTA rule:

#+begin_example
E = s * B
pressure = clamp(2 * (1 - E/k), 0, 1)
smooth = pressure^2 * (3 - 2*pressure)
rho = 0.5 + 0.4 * smooth
#+end_example

Here =k= is requested output count.  The rule remains at 0.5 when expected passing capacity
=E>=k= and approaches 0.9 under severe shortfall, permitting a stronger demotion while retaining
strict headroom.

** GPU kernel design

FAVOR has separate JIT kernel fragments.  The bitset check and penalty are fused into random-node
and child-node distance computation.  Only the lead lane of each distance team maps the source ID,
checks the packed bitset, adds the penalty, and writes the candidate once.  There is no separate
penalty kernel, extra global candidate buffer, or post-distance synchronization phase.

Retention-safe hot paths hoist bitset metadata per CTA, use direct packed 32-bit word loads when
possible, and reuse the read-only path.  Final compaction always removes rejected outputs.

The MSB-expanded marker and invalid sentinel must be normalized consistently during final
compaction.  This was fixed early because clearing the MSB of only one side caused invalid entries
to be counted as valid.

For sparse automatic retention, expanded rejected parents are retired after their children are
evaluated.  This is exactly the parent lifecycle already used by default filtered CAGRA; it prevents
expanded rejected nodes from permanently occupying the fused frontier/result buffer.

** MULTI_CTA traversal

Explicit FAVOR =MULTI_CTA= uses the same selectivity-adjusted breadth as default filtering:

#+begin_example
adjusted_B = round_up_32(k/s + (B-k)/sqrt(s))
num_cta_per_query = max(search_width, adjusted_B/32)
#+end_example

The configured =B= remains the value used in the FAVOR reference penalty.  No additional public
parameter was introduced for this adjustment.

* Benchmark infrastructure

cuVS-bench was extended to load FAVOR parameters, delta-d sidecars, persistent filter bitsets,
filtered ground truth, =max_queries= chunking, and diagnostic output settings.

The original filtered-ground-truth procedure was wrong: it filtered an already truncated ordinary
nearest-neighbor list.  A passing vector outside that short list can be closer than every retained
passing entry.  The correct procedure applies the bitset to the full dataset and computes the true
top ten passing vectors for every query.  All current comparisons use this exact filtered ground
truth and the identical persistent bitset for both methods.

* Established performance conclusions

** Static/reference FAVOR

The original static implementation is strongest for rare 1% SINGLE_CTA filters and can reach 0.90
where default does not.  It is not robust: BIGANN recall collapses at 10%, and beyond 10% its
SINGLE_CTA throughput is usually neutral or worse.

** Retention-safe FAVOR

Retention-safe scoring fixes the BIGANN 10% collapse and remains close to default in SINGLE_CTA,
but gives back part of static FAVOR's 1% advantage.

The controlled =MULTI_CTA= confirmation is the strongest positive result.  With batch size one,
retention-safe FAVOR reaches 0.99 on all six datasets at 1%, 10%, 50%, and 90% and improves target
QPS.  Reported batch-one QPS is reciprocal latency, not saturated 10k-query throughput.

** Automatic SINGLE_CTA retention

Automatic rho improves sparse recall materially on SIFT and BIGANN.  At 10% and above it normally
equals the fixed rho=0.5 path because =s*B>=k=.  In the full measured sweep it still misses 0.90 at
1% on GIST and both MSTuring scales.

** Deep traversal diagnosis

All six automatic-retention 1% diagnostic captures originally stopped at the derived iteration cap
with unexpanded frontier entries; exact hash-full counts were zero.  Expanded fixed budgets raised:

- GIST from 0.8301 at 133 iterations to 0.9139 at 256;
- MSTuring-1M from 0.7216 at 517 to 0.9254 at 2,048;
- MSTuring-10M from 0.6966 at 518 to 0.9255 at 3,584.

Most missing ground-truth neighbors were never discovered, rather than discovered and evicted.
Zero penalty did not repair the failures.  This is why further penalty-only tuning is unlikely to
solve sparse SINGLE_CTA by itself.

* Prior adaptive-termination experiment — rejected/default-off

The experiment defines =m=32= for =k=10= and, only after the old automatic budget =B0=, stops when
all prefix entries are valid, at least 16 pass, and the nearest unexpanded penalized distance is
worse than the prefix boundary.  A selectivity-derived =Bhard= bounds runtime.

It is GPU-local: warp 0 uses bitset tests, ballots, and population counts during the existing
parent-pickup phase.  It adds no second queue or buffer.  Diagnostics distinguish convergence from
the safety cap.

Matched 1% fixed-cell results:

| Dataset | B0 recall / QPS | Adaptive recall / QPS |
|-
| GIST-1M | 0.8300 / 15,635 | 0.9220 / 5,530 |
| MSTuring-1M | 0.7216 / 49,102 | 0.9450 / 9,204 |
| MSTuring-10M | 0.6966 / 49,148 | 0.8942 / 9,339 |

It fails both performance and MSTuring-10M recall gates.  Although 98.1--99.8% of queries stop by
the convergence condition instead of =Bhard=, they converge too late.  The large hard ceiling also
sizes the exact visited hash before launch, penalizing every query.

Normal behavior is unaffected.  Reproduction requires the internal switch:

#+begin_src sh
CUVS_FAVOR_EXPERIMENTAL_ADAPTIVE_TERMINATION=1  # direct binary
FAVOR_ADAPTIVE_TERMINATION=1                    # run_benchmarks.sh wrapper
#+end_src

Do not enable this by default without a new successful gate.

* Latest independent multi-seed B0 experiment — rejected

This staged experiment reruns existing automatic-retention SINGLE_CTA FAVOR one, two, or three
times with independent deterministic =rand_xor_mask= values and merges unique passing IDs by raw
distance.  Every round receives the ordinary derived =B0= budget.  It intentionally does not
preserve frontier or visited state, so it directly tests whether independent shallow starts alone
recover the missing neighbors.

Matched NVIDIA L4 results at 1% selectivity, =k=10=, =itopk=512=, three repetitions, and 10,000
queries are:

| Dataset | B0 recall / QPS | Two masks recall / QPS | Three masks recall / QPS | Adaptive recall / QPS |
|-
| GIST-1M | 0.83091 / 5,399 | 0.85061 / 2,694 | 0.85934 / 1,795 | 0.92545 / 2,016 |
| MSTuring-1M | 0.72220 / 28,785 | 0.73272 / 14,328 | 0.73580 / 9,414 | 0.94560 / 5,506 |
| MSTuring-10M | 0.69601 / 28,601 | 0.70795 / 14,206 | 0.71293 / 9,328 | 0.89432 / 5,560 |

The declared gate required either two or three rounds to reach recall 0.90 on all three workloads
and beat the same-machine adaptive control.  It fails: neither variant reaches 0.90 anywhere, and
the third GIST round is slower than adaptive.  The small marginal gains show that different starts
do discover some new neighbors, but repeat too much work to repair the depth shortfall.

The implementation is benchmark-only.  =favor_seed_masks= is parsed into a wrapper-private search
parameter, calls a private typed bridge that avoids recounting the exact bitset per round, and uses
a deterministic GPU merge ordered by =(raw distance, id)=.  No installed header or public API was
modified; an empty mask list follows the original dispatch.

Artifacts and reproduction live under =benchmarks/favor/multi_seed_b0/=.  The accepted report is
=results/report.md=, the full machine-readable table is =results/summary.csv=, and the gate is
=results/gate.json=.  Raw result JSON remains intentionally ignored.

* Latest saved-state retry diagnostic — full state required

The completed causal matrix tests whether a fresh B0 retry becomes useful when seeded from prior
passing outputs or from the actual pre-compaction unexpanded fused frontier. It also includes a
continuous-traversal oracle at the same cumulative budgets. All cells use the existing 1% filters,
=k=10=, =itopk=512=, and automatic retention-safe SINGLE_CTA FAVOR.

| Dataset | Rounds x B0 | Independent | Passing | Frontier | Combined | Oracle |
|-
| GIST-1M | 2 x 133 | 0.85067 | 0.84891 | 0.86338 | 0.86383 | 0.92247 |
| MSTuring-1M | 4 x 517 | 0.73792 | 0.73311 | 0.74867 | 0.74833 | 0.93077 |
| MSTuring-10M | 7 x 518 | 0.72170 | 0.70839 | 0.72464 | 0.72438 | 0.93026 |

The oracle clears 0.90 everywhere, while no restart variant does. Frontier/combined reseeding is
better than independent starts by 0.010--0.013 on GIST/MSTuring-1M but by only about 0.003 on
MSTuring-10M; it captures just 12--35% of the oracle gain. Passing-only retries rapidly become the
same search (last-round mean Jaccard is 0.9507, 0.9998, and 1.0000) and are worse than independent
starts at the final round count.

The benchmark-only implementation attaches explicit per-query initialization seeds through
thread-local private state and snapshots the terminal tagged frontier before filter compaction.
Flags retain validity, expanded state, and filter outcome. Per-query CSVs record newly recovered
ground-truth IDs, output overlap, frontier composition, retry-prefix size, candidate evaluations,
duplicates, and exact hash-full events. Forty-eight deterministic query traces retain compact
terminal-frontier binaries for each round.

The accepted conclusion is =full_in_kernel_state_required=. A reset-and-reseed accumulator is not
justified. If retry work continues, preserve the full traversal state or compact hard queries and
give the second pass a materially larger budget. Artifacts, runner, analyzer, and protocol live in
=benchmarks/favor/state_retry_diagnostic/=. The final report is =results/report.md= and the
machine-readable decision is =results/gate.json=. Timings are invalid by design.

* Termination plus forgetful-hash diagnostic (2026-08-02)

The next joint experiment is also complete. A benchmark-private opt-in enabled CAGRA's bounded,
periodically restored =SMALL= hash only for bitset FAVOR =SINGLE_CTA=, while a sparse shadow trace
recorded ordered passing top-10 state every 32 expanded parents. The predeclared gate would
implement a live condition only if one global prefix/gap/stability rule reached checkpoint recall
>=0.905 on GIST and both MSTuring 1% workloads.

The hash fails independently of termination. At =B0=, forgetful-hash recall is 0.28780, 0.16266,
and 0.17353, compared with exact-hash 0.83093, 0.72224, and 0.69609. Deep traversal reaches only
0.29276, 0.16266, and 0.17353 and underfills 72--95% of queries. There are zero hash-full events;
periodic forgetting instead causes large repeated-node traffic and prevents enough distinct
passing results from surviving.

The disposition is =reject_forgetful_hash_no_live_v2=. No live v2 termination path was added.
Ordinary filtered CAGRA still forces the exact hash, and no installed header or public parameter
changed. See =termination_hash_diagnostic/FAVOR_TERMINATION_HASH_DIAGNOSTIC.org= and
=termination_hash_diagnostic/results/report.md=.

* Recommended continuation

The next high-value work is sparse =SINGLE_CTA=, not MULTI_CTA.

1. Do not continue tuning the one-pass virtual-prefix condition; it is already a clear negative.
2. Do not implement an in-kernel retry accumulator whose rounds merely reset state and change
   =rand_xor_mask=; the completed focused matrix rejects that mechanism.
3. Avoid a larger up-front =max_iterations= because it increases the exact visited-hash allocation
   for every query.
4. The saved-state diagnostic rejects passing-result and terminal-frontier reseeding into a fresh
   =B0= search. If retry work continues, compact the hard-query subset and either give it a
   materially deeper second pass or preserve complete traversal state: frontier order, expansion
   tags, rejected bridge nodes, and the visited hash.
5. Gate any such minimal prototype on these three 1% cells.  Acceptance remains Recall@10 >=0.90
   and higher QPS than default near that range; stop before a full matrix if the focused gate fails.
6. Do not use the native forgetful =SMALL= hash for sparse FAVOR. It collapses recall and underfills
   results despite zero hash-full events. Any hash-memory replacement must retain exact visited-set
   semantics.
7. Do not implement the fixed-multiplier stale-evidence rule.  Cross-family validation requires
   incompatible multipliers (2 on the easy controls, then 8, 16, and 32 on GIST and the two
   MSTuring scales).  The DEEP holdout and bitmap gate were intentionally not reached.

Preserving full CTA state is a larger traversal redesign, but it is now the only state-saving retry
path supported by the diagnostic. A compacted, materially deeper second pass is the smaller
alternative.
