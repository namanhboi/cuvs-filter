- Opt-in FAVOR scoring is implemented for packed bitset filters in =SINGLE_CTA= and =MULTI_CTA=.
- Default CAGRA remains the public default and its API behavior is preserved.
- The recommended implemented FAVOR policy is query-local, retention-safe scoring.  Setting
  =favor_retention_fraction= to zero selects automatic retention.
- On independent random bitsets, automatic retention helps the difficult sparse SINGLE_CTA cases,

** Terminology and rate convention

Let:

- =s= be the fraction of dataset rows that /pass/ the filter;
- =f= be the fraction rejected, so =f=1-s=;
- =B= be the effective/configured intermediate top-k used by the selected mode;
- =k= be the requested output count; and
- =delta_d= be the graph/dataset statistic.

The public =search_params.filtering_rate= is =f=, the /rejected/ fraction.  For example, a 10%
selective predicate has =s=0.10= and =filtering_rate=0.90=.  A cuVS bitset greenlights passing
source rows; its storage is already packed into machine words.

When FAVOR receives a valid caller-supplied =filtering_rate=, it uses that value.  When the value
is negative, bitset dispatch counts the passing bits once and derives =f=.  An empty passing set
returns invalid-ID and maximum-distance sentinels without launching the search.  cuVS-bench
precomputes the exact rate during search-parameter setup so this count is outside measured search
QPS.

“Fixed retention” in the current fair reports means =CAGRA_RETENTION_SAFE= with =lambda=1= and
=rho=0.5=.  It is not the same as the =REFERENCE= penalty, sometimes called “static FAVOR” in
older notes.

* How the search works

** Delta-d sidecar

Delta-d is computed after the dense CAGRA graph and dataset are attached.  Deterministic roots use
bounded breadth-first graph neighborhoods; candidate distances are ranked and the normalized gap
between ranks =alpha= and =beta= is averaged.  Roots with fewer than =beta= unique candidates
contribute zero.  Experiments use =alpha=10=, =beta=64=, and BFS depth 2, although the API default
for =beta= is 127.

The saved sidecar is versioned and bound to graph metadata, logical dataset contents, distance
metric, calculation parameters, and fingerprints.  Loading a corrupt or incompatible sidecar
fails rather than silently recomputing it.  The dense dataset must be attached before loading.

The current GPU computation uses a shared-memory open-addressed set for BFS duplicate detection,
stages each root once, and uses CAGRA-style 8/16/32-lane distance teams according to dimension.
This reduced GIST-1M generation from an unfinished 22-minute serial-reduction run to roughly 36
seconds on the L4.  The primary files are
=cpp/src/neighbors/detail/cagra/favor_delta_d.cuh= and
=cpp/src/neighbors/cagra_favor_delta_d.cu=.

The value need not exactly match FAVOR's HNSW-built graph.  A full 1M-row comparison using matched
=M=16=, maximum base degree 32, =ef_construction=64=, =alpha=10=, and =beta=64= differed by 2.072%
on GIST and 4.268% on MSTuring-1M.  That discrepancy is consistent with different graph topology
and does not explain the sparse-search failures.

** Penalty modes

The reference exclusion distance is

#+begin_example
D_reference = f * (B - s) * delta_d / (2 * s * B)
#+end_example

where =s= must be positive.  A rejected candidate receives =score=raw_distance+D=; passing
candidates retain raw distance.

Query-local mode measures a robust local distance spacing =g_q= from finite initial candidates:

#+begin_example
D_query = min(D_reference, lambda * g_q)
#+end_example

Retention-safe mode also limits how much headroom a rejected candidate may consume.  If =tau= is
the worst finite retained distance, =d= is the candidate's raw distance, and
=h=max(tau-d,0)=, then

#+begin_example
D_effective = min(D_query, rho * h)
score       = d + D_effective
#+end_example

With =0<rho<1=, the penalty alone cannot push the candidate past the current retained boundary.
The explicit midpoint is =rho=0.5=.

Setting =favor_retention_fraction= to =0= derives =rho= per search from expected passing capacity:

#+begin_example
E        = s * B
pressure = clamp(2 * (1 - E/k), 0, 1)
smooth   = pressure^2 * (3 - 2*pressure)
rho      = 0.5 + 0.4 * smooth
#+end_example

The rule stays at 0.5 when =E>=k= and approaches 0.9 under severe sparse-filter pressure.
SINGLE_CTA uses its internal top-k for =B=.  MULTI_CTA uses the caller's configured global
=itopk_size= before its traversal-breadth adjustment.

** Fused GPU path

CAGRA uses one bounded intermediate structure as both candidate frontier and provisional result
set.  FAVOR does not add a second global queue.  Filtering and scoring are fused into random-seed
and child-distance production; the lead lane maps the source ID, performs the filter test, and
adds the rejection penalty.  Final compaction removes rejected rows and writes sentinels for an
underfilled suffix.

Sparse automatic retention retires a rejected parent immediately after its children are
evaluated.  This mirrors default filtered CAGRA's parent lifecycle and prevents an expanded bridge
node from occupying the fused buffer forever.

The corrected hot path in =1bba08d8=:

- honors a valid caller-supplied rate and counts the bitset only for a negative rate;
- hoists bitset metadata and layout checks once per CTA;
- directly loads the already packed 32-bit bitset word when its layout permits;
- uses that direct test when retiring rejected automatic-retention parents;
- defers query-penalty and cutoff work until an iteration will expand a parent;
- preserves the earlier timing in instrumented diagnostic kernels; and
- replaces repeated invalid-removal scans with one stable compaction pass.

The packed lookup does not create another copy of the query filter and consumes no extra full
bitset storage.  It is a specialized access path over cuVS's existing packed bitset.  Default
CAGRA keeps its normal generic filter path.

** MULTI_CTA breadth

FAVOR MULTI_CTA uses the same selectivity-derived breadth expansion as default filtered CAGRA:

#+begin_example
adjusted_B        = round_up_32(k/s + (B-k)/sqrt(s))
num_cta_per_query = max(search_width, adjusted_B/32)
#+end_example

Each CTA performs a partial search for the query; MULTI_CTA combines CTA-local results.  It is not
one CTA per candidate.  The configured =B= remains the value used by the reference penalty and by
automatic-rho selection.

* C++ use

** Compute and persist delta-d

The following is the essential sequence after building or deserializing an index with an attached
dense dataset:

#+begin_src cpp
cuvs::neighbors::cagra::favor_delta_d_params dd_params;
dd_params.alpha     = 10;
dd_params.beta      = 64;
dd_params.bfs_depth = 2;

float delta_d = cuvs::neighbors::cagra::compute_favor_delta_d(
  res, dd_params, index);
cuvs::neighbors::cagra::save_favor_delta_d(
  res, "cagra_g32_ig64.index.delta_d", dd_params, index, delta_d);

// In a later process, after loading the matching graph and attaching its dataset:
delta_d = cuvs::neighbors::cagra::load_favor_delta_d(
  res, "cagra_g32_ig64.index.delta_d", dd_params, index);
#+end_src

** Run automatic-retention FAVOR

This sketch uses cuVS's standard bitset constructor from rejected source IDs.  The bitset object
must outlive the search.

#+begin_src cpp
auto removed_ids = raft::make_device_vector<int64_t, int64_t>(
  res, number_of_rejected_rows);
// Fill removed_ids with source IDs rejected by this batch-wide predicate.

cuvs::core::bitset<uint32_t, int64_t> passing_bits(
  res, removed_ids.view(), index.size());
cuvs::neighbors::filtering::bitset_filter<uint32_t, int64_t> filter(
  passing_bits.view());

cuvs::neighbors::cagra::search_params params;
params.algo                     = cuvs::neighbors::cagra::search_algo::SINGLE_CTA;
params.itopk_size               = 512;
params.search_width             = 1;
params.filter_mode              = cuvs::neighbors::cagra::filtering_mode::FAVOR;
params.filtering_rate           = rejected_fraction;  // f = 1 - passing selectivity
params.favor_delta_d            = delta_d;
params.favor_penalty            =
  cuvs::neighbors::cagra::favor_penalty_mode::CAGRA_RETENTION_SAFE;
params.favor_penalty_lambda     = 1.0f;
params.favor_retention_fraction = 0.0f;  // automatic rho

cuvs::neighbors::cagra::search(
  res, params, index, queries, neighbors.view(), distances.view(), filter);
#+end_src

Use =filtering_rate=-1= only when the same batch-wide bitset applies to the search and counting it
once is acceptable.  The current API cannot supply a distinct rate or bitset per query.  For fixed
retention set =favor_retention_fraction= to =0.5=.  To obtain default CAGRA, set =filter_mode= to
=DEFAULT= and omit all FAVOR fields.

FAVOR validates the delta, lambda, rho range, algorithm, persistent setting, hash mode, and filter
type.  Filtered FAVOR requires the exact visited hash; the forgetful =SMALL= hash is rejected.

* Current evidence

** Fair GPU result

[[file:FAIR_RETENTION_FAVOR_SINGLE_MULTI_CTA_REPORT.org][FAIR_RETENTION_FAVOR_SINGLE_MULTI_CTA_REPORT.org]] contains only the latest L4 plots for
default, fixed retention (=rho=0.5=), and automatic retention (=rho=auto=) on GIST-1M, BIGANN-1M,
and MSTuring-1M at 1%, 10%, 50%, and 90% selectivity.

- SINGLE_CTA: automatic retention is valuable in some 1% cells, but GIST and MSTuring still do not
  bracket recall 0.90 in the selected current sweep.  At 10--90%, all three methods are generally
  close, with small dataset-dependent differences rather than a consistent FAVOR win.
- MULTI_CTA: there is no general advantage.  Default wins some cells, fixed/automatic retention
  win others, and sparse automatic retention can spend substantially more work.  Do not claim the
  large cross-hardware advantage shown by older reports.

The regression check in [[file:MULTI_CTA_RETENTION_REGRESSION_REPORT.org][MULTI_CTA_RETENTION_REGRESSION_REPORT.org]] proves that the apparent loss was not a code
regression.  At identical fixed-work cells on one L4, the normalized fixed-path GPU-time ratio
between the historical and candidate code was =1.0008= with bootstrap 95% interval
=[0.9994,1.0021]=.  Fixed retention was 2.08% faster than default in the historical checkout and
2.00% faster in the current checkout.  The misleading old/new comparison mixed A30 and L4 data
and time-limited with fixed-work measurements.

** Sparse SINGLE_CTA diagnostics

Deep continuous traversal with exact state can exceed 0.905 recall on the independent-bitset hard
cells, so high recall is possible.  The hard part is choosing and paying for the required budget:
GIST rose from 0.8301 at 133 iterations to 0.9139 at 256; MSTuring-1M from 0.7216 at 517 to 0.9254
at 2,048; and MSTuring-10M from 0.6966 at 518 to 0.9255 at 3,584.

Rejected approaches are retained as evidence, not production recommendations:

- adaptive one-pass termination recovered recall but reduced throughput sharply;
- two or three independent B0 rounds mostly repeated work and never reached 0.90 on the hard
  cells;
- restarting from passing outputs or a terminal-frontier snapshot captured only 12--35% of the
  continuous-state oracle gain;
- the periodically forgotten =SMALL= visited hash collapsed recall despite zero hash-full events;
- a global progress multiplier did not generalize across dataset families; and
- an E2E/LightGBM-style budget predictor could model work offline, but no reliable GPU-friendly
  budget rule demonstrated enough savings to justify integration.

These results mean preserved continuous state works, not that it fits an acceptable GPU budget.
Penalty-only tuning also cannot solve nodes that are never discovered.

** Correlated YFCC evidence from the CPU oracle

The companion FAVOR repository evaluates a 10M-row YFCC CAGRA graph with per-query conjunctive
metadata.  Automatic retention at deep work sees 0.9780 of exact ground truth but returns 0.8726
from the mixed fused queue.  A passive raw-distance passing top-k accumulator returns the seen
neighbors and first clears 0.905 separately on both arities at 15,138 parent expansions and
174,339 mean exact distance evaluations.  A dual frontier saves only 6.9% distance work at its
first sampled target crossing, below the 20% gate.

The accumulator therefore identifies a real output-retention mechanism, while its B0 recall of
0.6720 shows that candidate selection within the ordinary budget remains unsolved.  This is CPU
algorithmic evidence, not a CUDA QPS result.

* Implemented SINGLE_CTA UDF FAVOR

The phase-one path deliberately does /not/ extend =udf_filter= with exact per-query rates.  FAVOR
always samples the supplied predicate on GPU, even when its scalar hint is populated.  A zero-hit
sample uses the conservative =1/sample_count= floor and remains underresolved; on the stratified
YFCC workload this occurs for 23.3% of queries.

The JIT payload now separates predicate kind, opaque data, query offset, private sampled rates, and
the accumulator toggle.  Only nonpersistent SINGLE_CTA retention-safe automatic mode is accepted.
The bounded CTA-local accumulator has capacity exactly =k=, retains passing nodes only, deduplicates
internal IDs, and sorts by =(raw distance, internal id)=.  At L=512, W=2, k=10 on L4 it adds 84
dynamic shared-memory bytes and changes measured occupancy from 15 to 14 active CTAs/SM.  It is
traversal-passive: B0 legacy and accumulator diagnostics have identical exact distance work and
GT-seen rate, while recall changes from 0.5384 to 0.6645.

cuVS-bench accepts a generic dataset =filter= descriptor.  The first adapter,
=spmat_contains_all=, parses strict BigANN sparse matrices, uploads only row offsets and columns,
and applies the exact predicate =query_tags subset_of candidate_tags=.  Query offsets are carried
through benchmark batching without changing the public cuVS API.  CPU validation after timing
rejects predicate violations and malformed underfill sentinels.
