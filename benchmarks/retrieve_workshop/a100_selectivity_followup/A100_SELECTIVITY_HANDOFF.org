* Stages, outputs, and interpretation

=run.sh all= builds the A100 binaries, executes the tests, runs =real=, =low=,
and =correlation=, analyzes each stage, and creates
=$HOME/$(basename "$RETRIEVE_SELECTIVITY_RUN_ROOT")_results.tar.gz=. To resume,
export the original =RETRIEVE_SELECTIVITY_RUN_ROOT= and run the needed stage:
=run.sh real=, =run.sh low=, =run.sh correlation=, =run.sh analyze=, or
=run.sh bundle=. Run =run.sh matched-control= after =correlation= only if its
outcome needs a matched-initialization attribution check. A second =bundle=
will refuse to overwrite the first immutable archive.

This is a new =k=10= result root; the paper's original graph, bitmaps, and
bundles remain unchanged. It uses the degree-64 ArXiv-large CAGRA index,
=max_queries=2048=, Base/Retain native initialization, and NaviX =W*D=
passing seeds. The graph path uses three repetitions per point, retunes the
six paper B0 cells, then tries two deep cells at requested depths through
7,569 iterations until 0.95 valid-GT recall is reached or the sweep is
exhausted. Each depth is capped at the legal SINGLE_CTA visited-hash limit;
duplicate saturated cells are skipped. For degree 64, the L=512, W=2 cap is
4,092 iterations for Base/Retain and 2,046 for NaviX. Exact bitmap KNN uses
three timed repetitions and native-L2-cutoff validation.

=real= uses all existing <1% EM/EMIS/R queries and equally sized deterministic
1–3% controls within each workload; it copies the official ground truth.
=low= uses independent random bitmaps at 0.01%, 0.03%, 0.1%, 0.3%, and 1%
global passing fractions on the first 2,048 ArXiv queries. =correlation=
uses 10%, 25%, 50%, 90%, and 99% fractions with random and positively
correlated conditions. The positive condition samples passing IDs from each
query's exact nearest 1,024; observed local passing fractions are recorded.
Synthetic ground truth is generated before graph benchmarking.

=analysis/selected.csv= reports target status, selected QPS and recall, and
maximum measured recall for each method/cohort; full frontiers are in
=analysis/graph_summary.csv=. EM's 24-query and R's 14-query real cohorts are
exploratory for throughput: compare methods within the same cohort, not with
the paper's 10,000-query throughput values. The 90% and 99% cases are
near-unfiltered controls, not the main correlation evidence. Do not make a
paper claim until =run.sh analyze= succeeds and all exact controls pass.

The bundle includes source and generated-data hashes, configs, raw
repetitions, and analyzed CSVs, but omits large vector and bitmap payloads.

* Negative-correlation extension

The negative condition keeps each query's global bitmap cardinality equal to
its random and positive counterparts. If global passing is =s= and positive
nearest-1,024 passing is =p+=(1+s)/2=, negative nearest-1,024 passing is
=p-=s^2/p+=2s^2/(1+s)=. Therefore the negative local/global ratio is the
reciprocal of the positive ratio. The five expected local passing fractions
are approximately 1.8%, 10%, 33.3%, 85.3%, and 98.5% for global rates 10%,
25%, 50%, 90%, and 99%. These are controlled query-local bitmaps, not shared
metadata labels. The first 2,048 queries, exact nearest-1,024 IDs, graph,
binary, and exact-control policy are the same as in the prior study.

* Strict matched-recall refinement

The original =analysis/selected.csv= picks the fastest point with recall at
least 0.950, even when that point overshoots the target substantially. It is
not a matched-recall QPS comparison. The separate =tight-match= stage keeps
the completed run immutable and measures all 21 cohorts and all three graph
methods against the closed =[0.950, 0.951]= recall@10 window. Every one of
three final repetitions must be inside the window; a method without such a
point is labeled =unmatched= and excluded from matched QPS comparisons.

#+begin_src sh
export RETRIEVE_SELECTIVITY_REFERENCE_ROOT=/data/retrieve_workshop_runs/a100_selectivity_20260928T070431Z
export RETRIEVE_SELECTIVITY_MATCHED_ROOT="$HOME/a100_selectivity_matched_$(date -u +%Y%m%dT%H%M%SZ)"
benchmarks/retrieve_workshop/a100_selectivity_followup/run.sh tight-match
#+end_src

Keep =RETRIEVE_SELECTIVITY_MATCHED_ROOT= when resuming. The optional second
argument selects =calibrate=, =finalists=, =analyze=, or =bundle=. The runner
reuses the frozen query, bitmap, ground-truth, graph, and exact-control inputs.
It performs one-repetition calibration over integer requested =L=, width 1
or 2, and explicit traversal budgets, then runs in-window finalists in batches
of up to four for three repetitions. If a batch misses the strict window, it
tries the remaining calibrated settings until one passes or none remain.
=analysis/matched_selected.csv= gives each method's
status, achieved recall range, QPS, selected parameters, and nearest misses;
=analysis/calibration_points.csv= records the measured search points, and
=analysis/matched_comparisons.csv= contains pairwise QPS only where both
methods passed the strict recall gate. No
interpolation or upper-window relaxation is used. Recall resolution is coarse
for the 14- and 24-query real cohorts, so they may remain unmatched unless a
setting achieves exactly 0.950. The new bundle omits large bitmap payloads.

* Targeted overshoot rescue

The widened run still has three unmatched NaviX pairs whose nearest points
straddle the target but jump over the =[0.950, 0.952]= window. The rescue
stage probes only those pairs, with the existing W x D seed policy, widths 1
and 2, a small requested-L neighborhood, and every legal integer traversal
cap around each measured crossing. Ceiling cases are left unmatched because
their legal maximum is already below the target or above the upper bound.

The strict run supplies the one-repetition calibration frontier. The widened
run supplies the previously confirmed finalists so the rescue analysis keeps
all 43 existing matches and adds only newly confirmed rescue matches:

#+begin_src sh
export RETRIEVE_SELECTIVITY_REFERENCE_ROOT=/data/retrieve_workshop_runs/a100_selectivity_20260928T070431Z
