# Native CPU context pipeline

This directory produces the **CPU context** curves for the RETRIEVE workshop study. It runs the
already-built native FAISS-NaviX and ACORN bitmap adapters against the already-built graph
artifacts. It does not build an index and it does not modify either external repository.

The plotted methods are:

- FAISS-NaviX;
- reference ACORN-1; and
- reference ACORN-gamma.

The two `ACORN-* + NaviX seeds` variants are non-reference controls. They are retained in CSV/JSON
tables but are deliberately excluded from the Pareto figure.

## Interpretation boundary

**Do not use these measurements to make absolute CPU/GPU speedup claims.** The CPU and GPU runs use
different graph families, graph construction parameters, execution resources, and implementation
stacks. These curves provide qualitative, system-level context about recall-versus-throughput
behavior. A CPU/GPU overlay is not generated by this pipeline.

The native CPU adapters unpack each packed bitmap shard to their dense byte-mask API outside the
timed search call. Their reported QPS is therefore the native search API's QPS, not an end-to-end
bitmap-adapter measurement. This must be stated anywhere the numbers are used.

## Frozen production protocol

- Workloads: YFCC-10M and ArXiv EM, EMIS, and R.
- Queries: exactly 10,000 per workload. YFCC consists of four 2,048-query shards and one
  1,808-query shard; every ArXiv workload has one 10,000-query shard.
- Search sweep: `efSearch={10,15,20,25,30,50,100,250,500,750}`.
- Repetitions: three, stored in separate `rep_01`, `rep_02`, and `rep_03` trees.
- Search threads: FAISS-NaviX uses 16 threads on ArXiv and 32 on YFCC; all ACORN methods use 32.
- Query chunks: 10,000 on ArXiv and 512 on YFCC. The latter is the previously measured
  memory-bounded chunk gate winner.
- Metric/result count: squared L2 and `k=10`, as implemented by the native adapters.
- Methods are executed serially. Graph construction is never included in a run.

Graph parameters and their provenance are frozen in `run.py`. In brief, YFCC FAISS-NaviX uses the
JAG setting `M=64, efConstruction=200`; ArXiv FAISS-NaviX uses the adapter's fixed control
`M=32, efConstruction=200`. ACORN-1 uses `M=32, gamma=1, M_beta=32,
efConstruction=200`. Workload-specific ACORN-gamma parameters are EM `(16,10,24,160)`, EMIS
`(16,15,24,240)`, R `(32,12,24,384)`, and YFCC `(64,30,64,1920)` in the order
`(M,gamma,M_beta,efConstruction)`. The runner records the graph build CSV, byte size, modification
time, and a fast sampled fingerprint in every run's provenance.

## Run

First perform a read-only preflight:

```bash
/home/ubuntu/micromamba/envs/cuvs/bin/python \
  benchmarks/retrieve_workshop/cpu_context/run.py --preflight
```

Then launch the production run. The runner creates a new run directory atomically and refuses to
reuse one, so earlier measurements cannot be overwritten.

```bash
/home/ubuntu/micromamba/envs/cuvs/bin/python \
  benchmarks/retrieve_workshop/cpu_context/run.py \
  --results-root /home/ubuntu/retrieve_cpu_context_results
```

An optional `--run-id` may be supplied, but it must not already exist. Each command, environment,
log path, start/end time, return code, hardware snapshot, repository revision, binary fingerprint,
dataset manifest, and graph artifact is recorded under that run directory. A failed run is
preserved and is never silently resumed.

Analyze a completed run with:

```bash
/home/ubuntu/micromamba/envs/cuvs/bin/python \
  benchmarks/retrieve_workshop/cpu_context/analyze.py \
  /home/ubuntu/retrieve_cpu_context_results/<run-id>
```

The analyzer rejects missing/extra shards, an aggregate query count other than 10,000, incomplete
`efSearch` curves, incorrect thread/chunk settings, filter violations, malformed invalid sentinels,
or duplicate output IDs. For YFCC it computes QPS as `10000 / sum(all five shard seconds)`; it never
averages shard QPS. It emits:

- `analysis/per_rep.csv` and `.json`;
- `analysis/summary.csv` and `.json` with median/min/max over the three repetitions;
- `analysis/seeded_acorn_summary.csv`, `.json`, and `.md`; and
- `analysis/cpu_context_pareto.png` and `.pdf`, a 2x2 linear-y figure whose y axes start at zero.

Run the non-expensive static and synthetic checks with:

```bash
/home/ubuntu/micromamba/envs/cuvs/bin/python \
  benchmarks/retrieve_workshop/cpu_context/test_pipeline.py
```
