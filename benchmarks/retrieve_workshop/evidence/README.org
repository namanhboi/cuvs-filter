#+TITLE: Frozen Supporting Diagnostics

This directory preserves compact evidence used for claims that are not recomputed by the final
QPS--recall sweep.  Historical diagnostic files were copied byte-for-byte on 2026-08-19 from the
=favor-filtered-search= checkout at =/home/ubuntu/cuvs-filter=; raw multi-megabyte traces and result
arrays remain in that checkout.  Deterministic workload statistics and the duplicate-safe YFCC
B0 summary are generated in the isolated checkout from SHA-256-bound inputs.  The final paper
treats all of these as separate diagnostics, not as points in the three-repetition performance
experiment.

=diagnostic_manifest.json= is the machine-readable inventory consumed by the paper staging script.
The script verifies every listed artifact against its SHA-256 before publishing the final-results
sentinel, so stale performance summaries cannot be combined with silently changed diagnostics.

* Accumulator and YFCC discovery evidence

- =PASSING_ACCUMULATOR_DESIGN_AND_EVIDENCE_REPORT.org= documents the accumulator design.  Its
  historical GT-seen versus returned-recall numbers used slot-counted output semantics and are not
  authoritative for the paper's numeric selection-loss claim.  That claim must come from the
  separately generated schema-8, degree-64, distinct-output YFCC summary.
- =yfcc_b0_g64_distinct_output_summary.json= is that authoritative same-graph 1,000-query B0
  diagnostic.  It was generated from clean commit
  =d2b565e9786cecf235b2b382b377243cd8c9f348= and binds the raw JSON, schema-8 query
  summaries/result arrays, benchmark and library, G64/IG128 graph, dataset, queries, GT, and
  predicate metadata by SHA-256.  It reports Base GT-seen =0.7186=, Base returned recall
  =0.5416=, and Retain returned recall =0.7186= under distinct-valid-output set semantics.
  =summarize_yfcc_recall_diagnostic.py= enforces the corresponding configuration, schema,
  correctness, per-query GT-discovery equivalence, and accumulator-completeness gates before
  hashing inputs.  It independently reconstructs each output's GT-rank mask and requires Retain's
  mask to equal its seen-GT mask query by query; it also recomputes distinct recall, duplicate rate,
  and output count from the archived result-ID arrays and GT rather than trusting counters alone.
  =yfcc_b0_schema8_g64_sources/= is the durable source bundle: raw/config JSON, both schema-8
  manifests and query summaries, both result-ID arrays, and the exact 1,000-query GT matrix.  Each
  file is individually hashed in =diagnostic_manifest.json=.
- =YFCC_RECALL_ROOT_CAUSE_REPORT.org= documents B0 versus continuous deep traversal.
- =workload_selectivity_summary.json= derives exact per-query selectivity distributions directly
  from all 10,000 resident bitmap rows for each workload.  It binds every source manifest, bitmap,
  and fixed-width GT file by SHA-256, including the exact valid-GT-slot totals used in the long
  report.  =summarize_bitmap_selectivity.py= is the corresponding bounded-memory
  derivation tool; =test_summarize_bitmap_selectivity.py= covers continuously packed rows whose
  widths are not word-aligned.  In particular, YFCC's median selectivity is =0.00139485= and
  =0.7116= of queries have selectivity below 1%.
- =yfcc_navix/YFCC_NAVIX_ROOT_CAUSE_REPORT.org=, =diagnostic_summary.json=, and
  =counterfactual_oracle.csv= document the older in-kernel-seeded NaviX diagnostic.  Its oracle is
  a stratified 18-query hard-case sample and must not be described as representative of all YFCC
  queries or as the strict bitmap-seeded method used in the final sweep.

* ArXiv-EMIS locality evidence

=emis_locality/EMIS_LOCALITY_DIAGNOSTIC_REPORT.org= and the three JSON summaries document exact
query-distance locality, graph-edge locality, and traversal counters.  These data motivate a
region-entry hypothesis; they do not by themselves separate seed quality from traversal.  The
final matched-seed sweep is the causal control for that distinction.

* GPU resource and dynamic-work evidence

=gpu_resource_work_schema9/= is the compact archive for the paper's mechanism-level table.  It
contains six fixed =L=64,W=1,B0= YFCC/EMIS query summaries, the production kernel-resource logs,
configs, ordinary correctness output, and provenance for the exact benchmark binary, library,
GPU, Git state, and six instrumented sources.  =gpu_resource_work.json= SHA-256-binds all 22 table
inputs.  The schema-9 analyzer additionally proves query-by-query that Base and Retain read the
same graph rows, evaluate the same distances, and admit the same legal candidates, and verifies
that Retain adds exactly 84 dynamic-shared bytes without changing the active-CTA ceiling.
