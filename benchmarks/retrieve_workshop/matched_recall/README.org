#+title: B0-first matched-recall GPU experiment

This pipeline measures CAGRA-Base, CAGRA-Retain, and CAGRA-NaviX at Recall@10 0.80 on
YFCC-10M and 0.95 on ArXiv-EM/EMIS/R. It uses the paper's resident per-query bitmaps, identity
source IDs, single-CTA search, k=10, and complete cuVS-bench search-call timing.  The historical
built-in profile uses max_queries=512; explicit profiles may override it, and the A100
YFCC/ArXiv-large profile pins max_queries=2048 across calibration and finalists.

Calibration uses one full 10,000-query repetition. It first evaluates max_iterations=0 (B0),
enumerates W in {1,2,4}, and refines L in 32-element units through the single-CTA maximum of 512.
Explicit continuation is considered only if no B0 point reaches the workload target. Calibration
QPS is never paper data. Explicit continuation is also constrained by SINGLE_CTA's 20-bit normal
visited hash at its default 0.5 maximum fill rate; the generator rejects infeasible combinations
before launching cuVS-bench. Up to three finalists are rerun for three repetitions.

Run everything with:

#+begin_src sh
cd /home/ubuntu/cuvs-filter-retrieve
export RETRIEVE_RESULT_ROOT=/home/ubuntu/retrieve_workshop_runs/matched_recall_$(date -u +%Y%m%d_%H%M%S)
benchmarks/retrieve_workshop/matched_recall/run_matched_recall.sh all
#+end_src

The final paper inputs are =analysis/final_summary.csv=, =analysis/selected_points.csv=, and
=analysis/provenance.json=. For YFCC, each repetition is five serial search calls and aggregate
QPS is =10000 / sum(shard_seconds)=. No recall interpolation is performed.

For a completed A100 run whose EM/R NaviX =L=32= points exceed the upper target bound, the
=navix-refine= stage appends only the missing below-=L32= B0 executions and their three-run
finalists:

#+begin_src sh
export RETRIEVE_RESULT_ROOT=/path/to/a100_run/matched_recall
benchmarks/retrieve_workshop/matched_recall/run_matched_recall.sh navix-refine
#+end_src

It enumerates all distinct internal-capacity/B0 fingerprints for EM/R NaviX with requested
=10 <= L <= 31= and =W in {1,2}=, selects up to four fastest one-run points inside
=[0.950,0.952]=, and requires the final three-run selection to remain strictly inside that window.
Existing complete JSON is hash-independently validated against its config and repetition count
before being reused; partial JSON is never skipped silently.

* Tight paper-target refinement

The paper refinement uses requested, rather than rounded, =L=. CAGRA computes B0 from the caller's
requested =L/W= and then rounds the internal itopk capacity upward to 32 elements. Consequently a
request such as =L=65= uses a 96-element internal buffer but a B0 numerator of 65. The refinement
accepts =10 <= L <= 512=, tunes =W in {1,2}=, and accounts for the rounded capacity when checking
visited-hash feasibility.

It reuses the frozen broad sweep only to identify brackets, writes all new data to a separate
result root, calibrates every distinct =(rounded internal L, B0 iterations)= execution in each
bracket, reruns up to four in-window finalists three times, and finally reruns one selected point
per workload/method three times. The four intentionally deep YFCC/EMIS Base/Retain endpoints are
preserved. Run it with:

#+begin_src sh
cd /home/ubuntu/cuvs-filter-retrieve
export RETRIEVE_MATCHED_BASELINE=/home/ubuntu/retrieve_workshop_runs/matched_recall_b0first_20260821_v1/analysis/measurements.csv
export RETRIEVE_RESULT_ROOT=/home/ubuntu/retrieve_workshop_runs/matched_recall_tight_$(date -u +%Y%m%d_%H%M%S)
benchmarks/retrieve_workshop/matched_recall/run_tight_matched_recall.sh all
#+end_src

The closed target windows are =[0.800,0.802]= on YFCC and =[0.950,0.952]= on each ArXiv workload.
Inside a window the winner is the highest three-run median QPS, with no interpolation. The final
=paper_final= group contains exactly 12 configurations.
